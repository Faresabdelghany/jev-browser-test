# Example specs

Twenty-two specs against public demo and practice sites. Each exercises a runner path the smoke specs do not. The
credentials in the shop and HRM specs are the demo accounts the sites print on their own login pages. Run them all
with `python scripts/run_suite.py specs/examples/*.json --repeat 3 --workers 2`, one with `python scripts/run_test.py
specs/examples/<id>.json --headed`, and the `hrm-*` specs on one worker (`--workers 1`: the demo pre-fills the next
Employee Id when a form opens, and two forms opened in the same second collide). the-internet is a free Heroku app: a
cold start can add 25 s to a run's navigation, which the runner reports as such. The latest suite results are in
`docs/superpowers/measurements/README.md`.

| spec | site | flow | it exercises | result |
|---|---|---|---|---|
| `shop-checkout` | saucedemo.com, `standard_user` | login in `setup`, add a named product from six cards with identical "Add to cart" buttons, cart, a three-field form, overview, finish | identical labels told apart by their card, a multi-page path, three `data` values | pass, "Checkout: Complete!" |
| `shop-add-second-item` | saucedemo.com | add the second card's product, open the cart | a wrong pick shows up as an outcome; the product name is the evidence line | pass |
| `shop-checkout-problem-account` | saucedemo.com, `problem_user` | the checkout with the account the site documents as broken: a form field drops its input | a declared `bug` outcome with the app's own error as its evidence line | bug, "Error: Last Name is required" |
| `shop-checkout-error-account` | saucedemo.com, `error_user` | the checkout with the account whose Finish button does nothing | `control_had_no_effect` after a no-op click (flag `NO-EFFECT`), then BLOCKED with a suggested verdict; an `expect` spec: the documented breakage is its declared result | expected (undetermined, blocked) |
| `wiki-search` | en.wikipedia.org | type a term into the search box, the suggestions open, reach the article | a real autocomplete (`settle` ends on `options`), a very long page | pass |
| `todo-add-filter` | demo.playwright.dev/todomvc | add two todos, complete one, open the Active filter | TYPE_TEXT then PRESS_ENTER, two values into one field, hidden checkboxes under styled boxes, hash routing | pass, "1 item left" |
| `load-wait` | the-internet.herokuapp.com/dynamic_loading/1 | press Start, a loader runs for 5 s, a text appears | Jev choosing WAIT on a page with a timer; a WAIT ends the moment the page changes | pass, "Hello World!" |
| `notify-random` | the-internet.herokuapp.com/notification_message_rendered | click once; the notification is a random success or a random failure | the computed `flaky` verdict, each run keeping its own declared verdict; `text_in` on `#flash`, because the body copy contains both messages and a page-wide `text_contains` could never fail | flaky by design (pass / bug across repeats) |
| `modal-close` | the-internet.herokuapp.com/entry_ad | close the modal that opens on load | an overlay that hides the page; an absence as the pass statement | pass |
| `menu-random` | the-internet.herokuapp.com/disappearing_elements | nothing to click: is every menu entry listed? | an outcome decided on the start page (one step, two requests); an entry the page drops at random | flaky by design (bug / pass across repeats) |
| `web-form-submit` | selenium.dev/selenium/web/web-form.html | a text input, a textarea, a native select, a checkbox, a radio, Submit | SELECT, a checkbox and a radio under `<label>`s, two typed values into different fields, the GET query asserted with `url_matches` | pass, "Form submitted" |
| `add-remove-elements` | the-internet.herokuapp.com/add_remove_elements/ | Add Element twice, then one of the two Delete buttons | the same button twice on a page that changes each time, two identical buttons, a count asserted exactly with `text_in` `equals` | pass |
| `dynamic-controls` | the-internet.herokuapp.com/dynamic_controls | Remove (a loader), then Enable (a loader) | WAIT after two asynchronous actions; undecided steps while a loader is visible, waited out with backoff; `element_absent`; a pass worded on the messages and the buttons' new captions | pass, "It's gone!" |
| `forgot-password` | the-internet.herokuapp.com/forgot_password | type an e-mail, Retrieve password | the demo answers "Internal Server Error": a bug outcome whose evidence line is the server's own text, kept as an `expect` spec | expected (server_error) |
| `login-logout` | the-internet.herokuapp.com/login | Jev types the published username and password, logs in, logs out | a credential typed by Jev and masked through `secrets`, a two-page flow, `text_in` on `#flash` | pass, "You logged out of the secure area!" |
| `table-sort-due` | the-internet.herokuapp.com/tables | click the Due header of Example 1 | headers with no affordance at all (no role, tabindex, onclick or pointer cursor): not in Jev's table, so the run ends undetermined; an `expect` on the outcome only; `text_in` on the cells because `text_order` would be fooled by the second table; `after: {click: Due}` on the bug outcomes | expected (undetermined, low_confidence) |
| `hrm-add-employee` | opensource-demo.orangehrmlive.com, Admin / admin123 | login in `setup`, PIM, Add Employee, two names, Save | a slow admin single-page app: forms under loading overlays (`COVERED`), a sidebar with its own Search box, `NO-EFFECT` while Save is in flight, `field_value` on the saved record, `${RUN_STAMP}` in the last name, `settle_ms` 2500 | pass, "Jevtest Runner<stamp>" |
| `hrm-login` | opensource-demo.orangehrmlive.com | Jev types the credentials the page prints and logs in, so the Dashboard opens | the same app's login driven by Jev end to end: an empty shell before the app renders (`wait_for` in `setup`), the spinner after Login waited out, `text_in` on the topbar breadcrumb because the sidebar also says Dashboard | pass |
| `toolshop-search-cart` | practicesoftwaretesting.com | search, open a product from the results, add to cart, open the cart | a search box with its own button, card links, a toast and a header badge, `field_value` on the cart's quantity field | pass, "Proceed to checkout" |
| `hrm-pim-add-employee-list` | opensource-demo.orangehrmlive.com | login in `setup`; PIM, Add Employee, Save, Personal Details; Employee List, the name through the autocomplete, Search: exactly one record | `${RUN_STAMP}` in the last name (a fresh record every run), the autocomplete's 'Searching....' placeholder row and a `suggestion_not_found` bug outcome for a type-ahead that never offers the name, a marginal typing deferred while the form loads (`DEFERRED-TYPE_TEXT`), a two-sentence pass statement | pass, "(1) Record Found" |
| `hrm-admin-add-user` | opensource-demo.orangehrmlive.com | `setup` seeds an employee with plain Playwright; Jev opens Admin, Add, picks a role and a status from custom dropdowns, the employee through the autocomplete, types a username and a password twice, saves, filters the user list by the username | passwords through `secrets`, custom (non-`<select>`) dropdowns, `${RUN_STAMP}` in the username, `min_confidence` 0.6 against a transient autocomplete row; the list is filtered because the demo's table outgrows a page during a day | pass, the new username |
| `hrm-leave-assign` | opensource-demo.orangehrmlive.com | `setup` seeds an employee; Jev assigns a day of leave (autocomplete, a typed date in the demo's yyyy-dd-mm format, a leave type, Assign, Ok in the 'Balance not sufficient' dialog), filters the Leave List by status and employee, searches: one record | decisive facts that were toasts ('Successfully Saved', 'Failed to Submit: ...') captured as `announcements`; `no_records` with `after: {click: Search}`; a calendar popup that eats the next click, named in `notes` | pass, "(1) Record Found" |

`specs/compare/` holds the five specs of the Jev-versus-Playwright-CLI comparison
(`docs/superpowers/measurements/2026-09-24-claude-cost-comparison.md`). Copy any spec here as the starting point for
your own application, and keep specs for a private application under `specs/local/` (git-ignored).
